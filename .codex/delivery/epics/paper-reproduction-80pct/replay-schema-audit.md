# Task 5 replay snapshot and reset orchestration audit

Date: 2026-09-07. Source inspected at `aa34400`. Read-only source preparation; this report is the only new file written by this audit. No source edit, commit, simulator run, or tensor execution is claimed. The existing Task 1 coordination changes were preserved. Sources: recovery design Section 8, `scientific-wiring-audit.md`, Gym position/base lifecycle, current adapter trainer and its replay/filter implementations. Paths and line numbers below refer to that inspected source.

## Decision recommended for Task 5

Implement an explicit, versioned `new_replay_episode_v1` policy: restore a past physical configuration and the task geometry belonging to it, then start a new episode with deterministic histories, controller memory, filter state, timers, and delay phase. This satisfies design Section 8's permitted reconstruction option. It is an engineering delta, not exact continuation of the old episode or restoration of PhysX internals. Do not infer this policy from a blanket buffer clear; select and record it in the resolved profile.

Add `training/legged_gym/legged_gym/envs/base/legged_robot.py` to Task 5 ownership. A repair confined to `legged_robot_pos.py:reset_idx` cannot finish the transaction correctly because the base class computes observations and overwrites prior-action/velocity buffers after reset. Adapter ownership must include the trainer's `step`, `reset`, capture, observation/controller bootstrap, and filter state accessors, not only its replay class.

Full historical continuation should be unsupported initially unless every required state and runtime capability is available. Silently falling back from a requested full-history mode to the compact policy would change episode semantics; reject that configuration instead. The existing incomplete dictionary snapshots are migration inputs, not a certified full-history schema.

## Actual execution order and specific defects to account for

### Gym

`legged_robot_pos.py:237` runs navigation clip → alpha filter → low-level observation/history/encoders/body → stores `actions_orig` → inherited step. `_compute_actions:181` consumes body angular velocity/gravity, DOFs, filtered command and the *previous* `actions_orig`; its history uses a per-environment `episode_length <= 1` bootstrap. The current PD override `:164` uses joint state, gains, and current low-level action; the inherited velocity-controller mode is not the controller used here.

`legged_robot.py:93–150` then runs:

1. Reindex/store low-level `actions`; for every decimation substep compute torques, set forces, simulate, fetch, refresh DOFs.
2. Refresh root/contact tensors; increment episode/global counters; save old body twist; derive current body quaternion, velocities, gravity, feet state.
3. Position callback (`legged_robot_pos.py:460`) updates contact filtering and current distance/rays. It overrides, and does not call, the base callback's command-resample/random-push logic.
4. Termination updates collision onset, ACSI draws, initial/static/reach flags and timers; reward is computed for the terminal transition.
5. `reset_idx` writes replay or normal physical state, then currently clears common buffers for every reset row.
6. `compute_observations:671` first rewrites replay history, constructs proprioception, updates ray/goal histories and delay output, conditionally updates position history, builds navigation history.
7. Base post-reset epilogue unconditionally executes `last_actions[:] = actions[:]`, `last_dof_vel[:] = dof_vel[:]`, `last_root_vel[:] = root_states[:,7:13]`. Observation clipping and the returned reward/done follow in `step`.

Consequences beyond the previous scientific audit:

- At a terminating step, the old replay buffer has not recorded terminal root state: recording occurs only after reset in observation computation. Existing negative-index undo is therefore anchored to the last previously recorded frame, not an explicit collision-step ID. A new ring must define its anchor and phase directly rather than copy this indexing convention accidentally.
- `base_quat` is a view of `root_states[:,3:7]` (`legged_robot.py:522`), so replay assignment updates that view. The actual stale values are the separately computed body velocities/gravity, distance, rays and measured heights. Recompute all explicitly; do not base correctness on aliasing.
- `_get_perception` computes current `goal_local_pos` only *after* reward. `_reward_velo_dir:975` therefore currently combines current distance/velocity with the previous observation's goal direction. Extract a current geometry helper for the reset transaction; any change to regular-step reward timing must be recorded as an additional implementation delta rather than hidden in replay repair.
- Reset clears `last_actions` but not `actions` or `actions_orig`. Base epilogue immediately puts terminal low-level `actions` back into `last_actions`, and next `_compute_actions` consumes terminal `actions_orig`. `slr_commands` is also not reset; it enters the first returned navigation observation. These require explicit reset-row handling.
- `_get_rays(env_ids)` is not actually subset-safe: it computes subset points but reshapes heights as `self.num_envs` at `:506` and replaces full `self.rays`. Either retain a read-only all-environment geometry calculation with masked writes, or repair it into a masked helper. Passing a subset to the existing method is insufficient.
- Recalling `_post_physics_step_callback` after restore would read terminal contact tensors and mutate `last_contacts`; recalling `check_termination` would increment timers, draw ACSI again and reclassify the just-completed episode. Neither is a valid derived-state rebuild hook.

### IsaacLab adapter

`train_full_method_acsi_replay_ppo.py:1269–1347` runs filter → low-level history/body → carrier step → policy observation → custom reward/termination (including episode increment, position-history update, collision/timer state) → replay capture → navigation observation update → select/reset done rows → return.

- `_capture_replay_record:682` is after physics/reward but **before** `_update_observation:846`. Its saved root/DOFs and task counters are at t, while `sea_obs_hist` ends at t−1. Low-level history legitimately contains the controller inputs used to reach t, but the current replay restore returns the stale saved navigation history directly. Calling this one consistent snapshot time is unsupported.
- `reset:1016` calls `carrier.unwrapped.reset` first, then writes physical replay state and forwards/updates the scene (`_restore_replay_sample:660`), computes carrier observations, clears local buffers, restores selected saved fields, and sets two filter tensors to saved command. It leaves ray/goal histories and held perception at their cleared values, restores old episode phase, and bypasses `_update_observation` for replay. At the next nonrefresh tick the held rays/goals are thus 5/0 even while the returned history is old.
- Controller history bootstrap at `:1289` uses `(episode_length_buf <= 1).all()` across the batch. A reset row beside a running row shifts its history instead of using the intended initial fill. Replace this with a per-row bootstrap policy; test both mixed and all-reset batches.
- The queue-named command filter currently has no queue: `CommandDelayConfig.delay_steps == 0`; the state actually used by `TrainerCommandFilter.step` is `queue_filter.filtered`. `_filtered` is a mirror. Restore/reset via a public masked method updating both, not ad hoc private writes. Future queue modes require a different schema/policy contract.
- The replay buffer has no episode reset/identity method and updates `_last_collision_step` on every active collision frame, not onset. Normal and replay resets leave records eligible across episodes. Sampling currently does not consume collision metadata at all; introducing reservation/ack must enforce episode and generation ownership, not simply add a counter.
- The carrier task is the external `Isaac-Velocity-Flat-Unitree-Go2-v0`. This file disables two events and terrain curriculum but does not disable all carrier terminations/reset events. Carrier `step` may have auto-reset rows before the adapter captures root/contact state. Actual external manager behavior was not inspected/run here: a runtime contract must prove terminal capture precedes carrier auto-reset, or disable/defer that auto-reset through a supported carrier configuration/hook. Do not label a reset spawn as a pre-collision record.
- Observation-manager `compute()`, `sim.forward()` and `scene.update()` are global calls even during subset resets. Verify unaffected rows' observation-manager/sensor history and timestamps; the local masked tensor assignments alone do not establish independence. Contact reward uses max over `net_forces_w_history` (`:838`), so clearing only the adapter's collision flags is insufficient.

## Compact schema and ownership

Use preallocated structure-of-arrays tensors; environment/slot indices are implicit storage coordinates. One record is at boundary `S_t`: **after the completed policy physics interval and terminal reward/accounting, before reset**, with root/DOFs and task geometry captured at that boundary. There are no observation histories in the compact record, so whether normal navigation-history update is immediately before or after capture does not change the record. Record this phase in schema metadata and move Gym capture out of `compute_observations` into the explicit pre-reset boundary. Prefer capture before observation update in both runtimes, matching the adapter's current physical capture position.

| Ownership | Exact minimal contents | Lifetime / treatment |
|---|---|---|
| Ring payload | `root_state[13]` = world position 3, quaternion 4, world linear velocity 3, world angular velocity 3; `dof_pos[D]`, `dof_vel[D]` | Restore to the same environment and compatible scene. D=12 here. Schema records quaternion order: Gym xyzw, adapter wxyz; canonical representation plus explicit boundary conversion is preferable. No implicit interchange. |
| Gym task geometry | `position_targets[3]` | Restore with root. `env_origins`, terrain type/level and immutable terrain identity must match the source task generation; retain as episode context or validate by generation token. A replay does not select a new terrain/spawn. |
| Adapter task geometry | `start_cell[2]`, `map_origin_cell[2]`, `goal_cell[2]` | Restore before ray/goal recomputation. `room_id`, occupancy/resolution, scene origin, robot joint ordering and asset identity are validated episode/run context. |
| Per-slot identity | `episode_id:int64`, `step_id:int64`, `task_generation:int64` | `step_id` identifies the physical boundary; time derives from step ID and fixed policy dt. Store explicit simulation time if dt can vary. Environment, schema version, policy and coordinate convention are not repeated Python dictionaries per slot. |
| Per-env ring metadata | write index, valid length, current episode/task generation, last recorded step; collision-onset boundary; last-active collision flag; pending reservation token/slot/slot generation; requested/effective undo and status | Independent timelines; guard overwritten/stale/cross-episode candidates. Collision boundary is separate from task reward collision flags. No D2H `.item()` per push. |
| Run/episode context | schema/policy version, controller hashes, geometry/joint/frame metadata, profile and dt, immutable scene generation; optional reproducible reset seed/counter | Referenced, not copied into each record. Reject scene/task generation mismatch. |
| Cross-episode learning/accounting | `goal_levels` / `source_goal_levels`, curriculum update events, learner and RNG streams, aggregate episode/replay statistics | Not rewound. Apply the separately selected ACSI update rule once for the completed episode event. Physical terrain selection is distinct from scalar learning level. Terminal reward/done/timeout/bad-mask output belongs to the old transition. |

In this new-episode policy, old commands, actions, controller histories, sensor histories and timers are deliberately **not** snapshot payload: their complete reconstruction recipe below owns them. A scalar counter-based seed keyed by run seed, env ID, new episode ID and bootstrap stage can make noisy bootstrap reproducible without saving/restoring global RNG state or affecting other environments. Alternatively define a noise-free first bootstrap and record that delta. Current code uses batch-global RNG; unchanged global RNG consumption is not a claim this audit makes.

Do not duplicate mutable terrain or robot physical properties per slot. If carrier reset randomizes mass, friction, actuator parameters or other physics context, either suppress those mutations for replay and preserve the episode context, or restore supported parameters and validate generation. A scene mismatch is a fallback reason; root/DOFs alone cannot restore an arbitrarily randomized carrier.

## Reconstruction recipe: every relevant field gets a policy

At restored boundary `S_t`, create a new episode at local step 0 without advancing physics. Keep the original snapshot step ID in provenance, separate from new episode length. All bootstrap histories are tagged conceptually as synthetic samples from this one restored boundary, not real past acquisition times.

| State group | `new_replay_episode_v1` reconstruction |
|---|---|
| Physical derived state | After state writes, derive `base_quat`, body `base_lin_vel/base_ang_vel`, `projected_gravity` from restored world state. Refresh/invalidate carrier root/DOF/body caches through its supported API; regenerate joint-relative policy inputs from restored joint state and defaults. `feet_pos/feet_vel` need actual rigid-body/FK refresh if a configured consumer uses them; root assignment alone is not enough. |
| Geometry | Recompute current `distance`, `far_goal`, yaw/`goal_local_pos`, rays, measured-height grid, and any opening/clearance values. Gym heights/rays depend on restored root yaw/position and immutable terrain; adapter also needs restored map/goal cells and room origin. Derived values are not copied from terminal buffers. |
| Filter and command | Set Gym `nav_actions_orig`, `nav_actions_filtered`, `nav_actions_after_clip`, `slr_commands` to zero; adapter `slr_command` and both filter mirrors to zero. This makes first observation command consistent with the filter/controller starting state. First incoming navigation action applies the configured alpha recurrence from zero. |
| Low-level action state | Set Gym `actions_orig`, `actions`, `last_actions` and adapter `last_loco_action` to zero in their documented joint orders. Clear obsolete torque/actuator command targets or overwrite them before any forward/physics operation that can apply them. Neutral previous action is a declared controller bootstrap, not historical action restoration. |
| Velocity baselines | Initialize `last_dof_vel` to restored DOF velocity, `last_root_vel` to restored world twist, and `last_base_twist` to restored body twist. This avoids a synthetic acceleration impulse in optional inherited rewards; reset-row epilogue must preserve the chosen values. These fields do not affect the seven currently active position reward terms, but must be accounted for if those terms are enabled. |
| Low-level observation memory | Assemble fresh `slr_obs_buf` from restored body/joints, zero command and zero previous action; repeat into `slr_obs_hist[10,45]`. Recompute encoder outputs (`base_lin_vel_pred`, latent) when consumed. Do not call `_compute_actions` merely to bootstrap: it also draws noise and runs the body. Extract a pure frame-builder plus an explicit history bootstrap. Next control tick uses a per-row initial mask. Loaded JIT modules' hidden mutable state is not proven absent by file inspection; require stateless model contract or a supported per-row reset. |
| Perception history and holding | Repeat restored current rays into `rays_hist[10,41]`, current local goal into `goal_hist[10,2]`; set `rays_rand` consistently and held `delay_rays/delay_goal` to those same values. Acquisition/hold phase starts at new step 0. For timestamped delay, use a declared bootstrap sample at time 0 with age 0 and a validity/availability marker until real samples arrive; do not invent 40–80 ms of prehistory. |
| Navigation observation memory | Build fresh 55-vector from restored gravity, zero command, restored velocities, log-clipped held rays, held goal; apply declared bootstrap noise once, then repeat into `obs_history_buf` / `sea_obs_hist[10,55]`. Set flattened/clipped `obs_buf`. Never append a restored-state frame to terminal-state history. |
| Position history | Repeat restored XY position into all 10 slots of `pos_hist`, using Gym world XY / adapter local XY consistently. Start position-update phase at 0; do not fill zeros except where physical XY really is zero. |
| Episode/task state | `episode_length_buf=0`, `goal_hold_timer=0`, `stay_timer=0`; terminal `goal_reached_flag`, `stand_still_flag`, timeout/termination flags cleared for the new episode. `reach_goal` is derived from restored distance; `initial_=true`, `not_just_reset=false`, `static=false`; recompute geometric `fall_down` if maintained. Timers advance only at the next real termination evaluation. Preserve old output done/reward/timeouts separately. |
| Contacts and collision | Clear `feet_air_time`, filtered/previous contact latches, `collision_occurred`, `last_collision_active`, collision visualization points/counts for the new episode. Invalidate/clear carrier contact-sensor histories through supported masked reset and treat contact data unavailable until refreshed by actual physics. Do not assign zeros to a borrowed simulator contact tensor and call it recomputed contact. Initial-step penalty masks do not alone protect the unmasked >50 force reset. No terminal contact data may enter new-episode reward. |
| Accounting and learner | Finalize/reset per-episode sums once, retain total statistics and selected curriculum updates. Retain old done mask for PPO's `actor_critic.reset(dones)` (`ppo.py:160`); a replay remains an episode boundary. No PPO/optimizer history is rewound. Reset debug/trace data is provenance only. |

For the current active Gym reward terms, the next real reward uses fresh physical velocities/gravity, current rays/distance/goal direction, new position history and timers, contact state and initial/termination masks. Optional inherited action-rate/DOF-acceleration/feet-air-time rewards add the baselines above. Configuration should reject any newly enabled stateful consumer not covered by the selected reconstruction contract.

## Testable transaction spanning both call sites

The pure state machine returns a staged reset transaction; runtime code owns physical effects. Do not acknowledge inside `_reset_collision_replay` immediately after two tensor setters.

1. At `S_t`, preserve terminal reward/done/timeout/bad-mask and completed-episode statistics. Record eligible physical snapshots and collision **onset** boundary before destructive reset. Use explicit `record_step_ids`; terminal step t and requested undo d select `t-d`. Bootstrap new episodes with a step-0 record, so 151 slots can retain 0 through 150. Inclusive undo sampling is `randint(lo,hi+1)`, then explicit short-history clamp; record requested and effective distance. No-history/invalid candidates become fallback candidates.
2. Reserve selected candidates per environment without clearing collision metadata. Validate IDs, slot generation, episode/task generation, finite values, shapes and quaternion convention/norm before writes. A reservation points to an immutable staged clone of only selected compact rows so a later push cannot alter the pending sample.
3. Partition requested IDs into intended normal rows and reserved rows. Final committed/fallback sets are not yet known. Apply the selected curriculum/accounting event once, using saved terminal inputs. Replay restores source task geometry and must not run normal terrain/spawn selection.
4. Runtime writes root pose/velocities and DOF state, resets/invalidate relevant carrier managers and actuator commands for those rows, performs supported scene synchronization/FK/cache refresh, then rebuilds derived root/joint/perception state. Existing adapter order is root pose → root velocity → joints → `scene.write_data_to_sim` → `sim.forward` → `scene.update`; validate that no old actuator target is reintroduced and that global hooks leave nonreset rows untouched. Gym currently uses root-state setter then DOF-state setter; obtain runtime evidence for refresh semantics, do not claim that issuing setters alone verifies them.
5. Apply the complete compact reconstruction recipe. Build first observation through explicit masked bootstrap, without `check_termination`, reward, time advancement, history pushes, random ACSI selection, normal curriculum/spawn logic, or recursive reset. Stage the resulting observation until ready.
6. Finish normal/fallback rows through the normal reset path, including the same post-write derived-state bootstrap. Normal rows may select new task geometry according to existing rules; fallback must not silently skip it. Account for fallback only once.
7. In Gym base orchestration, compute/update regular observations only for nonreset rows, publish staged reset-row observations, then apply prior-state epilogue only to nonreset rows (or preserve reset-row reconstructed state explicitly). `compute_observations` can retain a compatibility no-argument entry point, but internal geometry/history/publish helpers need masks. In the adapter, capture/normal observation update/reset reconstruction must avoid a second update of reset rows and use per-row low-level bootstrap.
8. After physical write, reconstruction **and post-reset hooks** have succeeded, acknowledge exactly successful replay reservations; then begin their new ring episode and publish the step-0 compact snapshot. Cancel successful normal-reset fallbacks with explicit reason and invalidate their old ring episode. Final `normal_ids`, `committed_replay_ids`, `fallback_ids` must be disjoint and cover requested IDs. Return old transition reward/done with the new observation, never new-episode cleared done flags as the terminal output.

This order intentionally makes ack the final state commit. Reset code may return a transaction/mask to the base class; finalization occurs after the base observation/epilogue stage. With a compact schema it is unnecessary to place ack inside the physical-write helper.

Failure policy: a failed prevalidation leaves the source reservation unconsumed until explicit cancellation/fallback. If physical writes partially succeed and reconstruction fails, a normal reset of affected rows must write a complete new root/DOF/task state and rebuild everything before returning. Do not reuse a partially restored observation. A successful fallback explicitly cancels that reservation and records the reason; it is not a replay success. If the normal fallback also fails, propagate the error and do not return an observation or acknowledge replay. If a runtime batch setter has no per-row success reporting, treat the whole attempted subset as uncertain; do not claim partial success based only on the number requested. Keep nonterminal rows' records and state intact.

## Memory and performance budget at 2048 environments × 151 slots

There are 309,248 slots. Assumptions: D=12, float32 physical payload, three int64 identity fields per slot. Counts exclude allocator overhead and O(num_envs) ring/context metadata.

| Representation | Bytes/slot | Total |
|---|---:|---:|
| Compact Gym: 37 physical floats + 3 target floats + 24 identity bytes | 184 | 56,901,632 B = 54.27 MiB |
| Compact adapter: 37 physical floats + 6 cell floats + 24 identity bytes | 196 | 60,612,608 B = 57.80 MiB |
| Current adapter dictionary's numeric payload alone: 1,078 floats, three int64 timers/length, one bool | 4,337 | 1,341,208,576 B = 1.249 GiB |
| Five history arrays alone: SEA 550 + SLR 450 + rays 410 + goal 20 + position 20 floats | 5,800 | 1,793,638,400 B = 1.670 GiB |
| Full-history lower bound: those histories + 43 held perception floats + 37 physical floats + 3 goal floats + identity | 6,156 | 1,903,730,688 B = 1.773 GiB |

The last row is still incomplete: actions/filters, timers/flags, contact histories, controller/sensor internals and runtime state add more. Current adapter records use many per-env tensor objects and dictionaries; `_capture_replay_record` clones batched tensors and `push` clones slices again. Object and transient clone cost is additional to the numeric payload. Full snapshots with larger history windows multiply storage by both capacity and history length. Compact push must perform indexed slot writes proportional to active envs × fixed payload width, not shift capacity-length arrays.

Keep only one current copy of the five histories per environment: 2048 × 5800 B = 11.33 MiB, rather than repeating them in every snapshot. Reservation staging is proportional to the reset subset, not capacity. If exact continuation later becomes necessary, design event/frame rings with generation-checked references and sufficient retained spans (position history is sampled every 10 policy ticks), rather than nesting complete histories in each slot. Do not advertise exact physical continuation without runtime-state support even then.

## Small shared package and required evidence

Place the pure schema/ring/reset-policy contracts under packaged `training/rsl_rl/rsl_rl/replay/` (or the adjacent shared profile package selected by Task 2). `rsl_rl/__init__.py` has no simulator imports and `setup.py` uses `find_packages()`. Use Python-3.8-compatible type annotations for the frozen Gym stack. The pure module imports at most standard library and Torch; it must not import `legged_gym.envs` (which imports Isaac Gym), the trainer (which boots the app/parser), or `adapters.cbf_shield`.

Keep `adapters/collision_replay.py` as a compatibility adapter exporting existing class/config names. Legacy `push` arguments and `sample_pre_collision` can remain through a wrapper with deprecation/migration validation; sampling returns a reservation-backed view, while runtime consumers switch to explicit `reserve/ack/cancel/begin_episode`. Preserve existing scalar/batched return-shape compatibility where promised, but do not silently certify a legacy incomplete snapshot as historical restoration. Add public masked `reset_state/restore_state` on filter wrappers if needed; actual current compact use only needs reset.

Extract testable pure helpers for root-derived body frame math, goal geometry, observation/SLR frame assembly, history bootstrap, row partitioning, episode transition and post-step buffer update policy. Terrain raycasting remains a runtime/domain helper with masked output assignment. Pure helpers must receive explicit inputs; avoid calling the existing mutating callbacks, observation function, termination or reward functions as reconstruction shortcuts.

Required CPU evidence: explicit collision t/undo d target IDs; inclusive endpoints; independent wraparound/generations and normal/replay episode boundaries; snapshot alias isolation; pending reservation overwrite protection; injected failure before physical write, after physical write, during reconstruction and during post-reset epilogue; exact final partition and ack count; scripted mixed-env state demonstrating untouched neighbors; all rebuilt fields independent of deliberately poisoned terminal buffers; first returned observation and next low-level history/filter recurrence; step-0/step-1 bootstrap and delay hold phase; old transition done/timeout preserved; no duplicate timer/curriculum updates; capacity-scaling push work. Test base orchestration with a simulator-free lifecycle harness around the extracted policy, and static/AST proof that actual base/trainer methods call it in the right order. CPU fakes do not prove simulator writes.

Required runtime evidence remains separate: real multi-env Gym Rung 3G and relevant IsaacLab smoke must verify indexed writes/readback, restored first-observation values, contacts/sensor cache treatment, carrier auto-reset ordering, manager/actuator behavior, unaffected rows, and post-reset low-level action inputs. The existing forced replay smoke checks shapes/finiteness and sample/reset counts; those checks alone do not establish this contract. Both runtime validations are unexecuted by this audit.
